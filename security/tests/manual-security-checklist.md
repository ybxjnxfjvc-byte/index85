# Manual security checklist — index85

- [ ] Открыть кейс без авторизации и убедиться, что он не обещает доступ к закрытым системам организации.
- [ ] Проверить поля ввода пустым, длинным и содержащим `<img src=x onerror=alert(1)>` значением; разметка не должна исполняться.
- [ ] Проверить URL: пользовательские данные не должны появляться в query string без необходимости.
- [ ] Проверить DevTools → Network: зафиксировать фактические внешние endpoint; неизвестные запросы должны быть объяснены или удалены.
- [ ] Проверить localStorage/sessionStorage: там не должны храниться пароль, токен, телефон, e-mail или иные реальные секреты.
- [ ] Выполнить поиск по репозиторию по `token`, `secret`, `password`, `BEGIN PRIVATE KEY`, `ghp_`, `AKIA`.
- [ ] Проверить, что ошибки интерфейса не показывают stack trace, абсолютные локальные пути или конфигурацию.
- [ ] Проверить все внешние ссылки и границу перехода на сторонний ресурс.
- [ ] Проверить публикационный состав: нет исходных архивов, `.env`, локальных БД, профилей браузера, временных файлов.
- [ ] Сверить `security/docs/threat-model.md`: для каждого риска есть конкретный контроль или честно описанное ограничение.
- [ ] Запустить автоматизированные проверки из `security/tests/python` и соответствующие scripts/lab этого кейса.
